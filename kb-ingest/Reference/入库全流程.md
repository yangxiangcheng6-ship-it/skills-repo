# 智能入库全流程（kb-ingest）

> 本文件是 Dify 工作流「智能入库 (22).yml」（26 节点/31 边）与演进历史（(7)→(18)→(22)）的设计沉淀。技能包覆盖可脚本化步骤；MinerU 解析与 md_cleaner 清洗是 Dify 插件节点，在插件环境内执行。

## 全链路

```
用户文件(file) + 版本(version)
  → 路由（版本 → 老库管道 / MinerU 库 create-by-text）
  → 扩展名分流：.xls* 走老链（管道入库）；其余走 MinerU 链
  → MinerU Parse File（插件，188~378s 大文档）→ md_cleaner 清洗（插件）
  → 构造 create-by-text body → POST /document/create-by-text（blocking 等索引完成）
  → 取 doc_id → LLM 判断 file_role/doc_summary/doc_type → 打标 /documents/metadata
  → MinIO 写入 {version}/{file_name}.md + 更新 _index.json（追加 + 排序）
```

## 关键事实（2026-08-18/19 实测）

- **MinerU 支持 pdf/doc/docx/ppt/pptx/图片，不支持 xlsx** → xlsx 只走老库管道（扩展名分流 `not contains .xls`）
- **create-by-text 不带 metadata 参数**，打标必须单独调 `/documents/metadata`
- MinerU 插件：remote 走 `api/v4/file-urls/batch` 异步批处理+轮询；base_url 别带 /api/v4；插件拿到的文件 URL 是相对路径，docker/.env 必须设 `FILES_URL/INTERNAL_FILES_URL=http://api:5001` 并重建 api+worker，否则报 Invalid file URL
- md_cleaner **0.0.4 会把处理日志混进 text 输出污染 KB 正文和 MinIO 文件**（⏳/✅ 开头的日志块），0.0.5 已修复（日志改 create_log_message）；MinIO 里已污染的 md 需要重跑清洗
- **MinIO 对象不能直读文件系统**（xl.meta 分片），必须走 S3 API（AWS4-HMAC-SHA256 签名）；Dify 节点 endpoint 填 `http://minio:9000`（容器名）
- 凭据坑：AK/SK 复制粘贴带空格（" minioadmin"）→ S3 认证失败；排查套路：`docker logs minio` 没请求=节点没执行，有请求但 403=凭据错
- 插件节点配置：content/object_name 是 llm 型参数走 tool_parameters（可变量），AK/SK/endpoint/bucket 走 tool_configurations（is_team_authorization，**不随 DSL 走，导入后要重填**）
- **分支跳过不会阻止有外部输入的节点执行** → 流量控制靠代码守卫（空文本返回空 body）+ 条件分流（文本非空才建文档），不能靠 skip
- create-by-text 大文本变量可能截断 → 备用方案：清洗后 .md 走 `/v1/files/upload` + create_by_file

## 索引格式（_index.json）

```json
{"标准": ["Appendix A (210909 bilingual).docx.md", "..."], "偏离": ["..."]}
```

- 文件名含 .md 后缀，**排序后写入**——diff-expert 匹配平局时按文件名字典序取第一个，排序保证确定性

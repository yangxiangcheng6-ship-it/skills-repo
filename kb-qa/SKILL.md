# 知识库检索问答专家（kb-qa）

对标准/偏离两个知识库做切片级检索问答。机械步骤（拉清单/检索/合并切片）由脚本完成，判断步骤（文档匹配/回答/澄清）由 LLM 完成。

## 用途

- 单侧条款问答："违约责任怎么规定的"、"付款期限是多少"、"附录A里写了什么"
- 跨版本问同一条款："标准版和偏离版分别怎么规定付款"（注意：这是问"两边各怎么规定"，不是对比差异）
- 追问细化："里面怎么规定的"、"还有别的吗"（沿用上一轮检索词）
- 文件组成/附件清单类："框架协议由哪些文件组成"、"有哪些附件"

## 何时触发

- 用户询问某份文档中某个条款/内容/数值是怎么规定的（单侧询问）
- 用户要求按版本（标准/偏离）或文档类型检索知识库后回答
- 用户追问上一轮检索的话题

**话题过滤（第一道门槛）**：只处理"检索知识库内容回答问题"类需求。
- 对比类（"对比""差异""改了什么""有什么不一样"）→ 说明不适用，建议换 diff-expert
- 入库/打标/上传类 → 说明不适用，建议换 kb-tagger
- 其他无知识库检索意图的闲聊 → 直接正常回答，不调用本技能

## 执行流程（严格按顺序）

### 第 1 步：拉取文档清单

```bash
python Scripts/list_docs.py
```

输出 `doc_list`（多行，格式 `[KB名] doc_type值 | 摘要 | 文件名`，来自标准/偏离两库）。
- 拉取失败（API 不可达）→ 向用户说明知识库服务不可用，不编造清单

### 第 2 步：LLM 匹配文档

```bash
python Scripts/match_prompt.py
```

生成文档匹配提示词模板（含结构化输出 schema）。把 doc_list 和用户问题代入模板，LLM 输出 `results[]`，每项 `{doc_type, version, query}`（query 为 5~15 字纯检索词）。

规则：
- 有对应文档行就用它；没有或明显冲突时按用户意图选最相关行
- version 以匹配行所在 KB 名为准（"标准"开头→标准，"偏离"开头→偏离）
- query 去掉"标准/偏离/哪个版本"等筛选词，保留内容关键词；具体条款用原文标题词（如"合同文件""服务费用和付款"）
- query 禁止输出文档类型词本身（"通用条款""主协议"是分类不是检索主题）
- **匹配不到任何文档 → 直接走第 5 步澄清流程**
- 追问上一轮话题：基于上一轮 results 合并检索词（新 query = 原 query + 追问词），doc_type/version 沿用

### 第 3 步：检索切片

对 results 的每一项执行（涉及多文档/多版本时逐项执行）：

```bash
python Scripts/retrieve.py "<query>" [--version 标准|偏离] [--doc_type 主协议] [--top_k 8]
```

- 默认同时检索标准+偏离两库；指定 `--version` 只检索该库（metadata 过滤）
- 检索配置：hybrid_search（bge-m3 向量 0.7 + 关键词 0.3）+ qwen3-rerank 重排
- 输出切片 JSON（含 content / document_name / score）

### 第 4 步：合并切片

```bash
python Scripts/merge_chunks.py <检索结果文件1> [<检索结果文件2> ...]
```

去重、按文档分组标注、每块截 6000 字。
- 合并后为空 → 走第 5 步澄清流程
- 有内容 → 把合并文本交给 LLM（第 5 步回答模板）

### 第 5 步：回答 / 澄清

```bash
python Scripts/answer_prompt.py      # 正常回答模板
python Scripts/clarify_prompt.py     # 澄清/报错模板
```

- **正常回答**：只基于合并切片回答，注明出处（文档名+片段），"哪些/有哪些/清单"类必须列全；切片不足时不要只说"无法回答"，列候选文档让用户确认要查哪一份
- **澄清**（匹配不到文档 / 检索无结果 / 服务报错）：说明情况 + 从 doc_list 中列出可能相关的文档（文件名+摘要）作为选项请用户选择，或请用户补充版本/文档名
- 检索 API 报错：如实说明错误，不编造内容

## 交付物

- 回答正文（基于切片，注明出处）
- 命中切片溯源（文档名 + 关键片段）
- 澄清时：候选文档清单 + 需要用户补充的信息

## 注意

- 脚本在技能目录下执行，cwd 已在技能包根目录（`python Scripts/xxx.py`）
- API 默认 `http://127.0.0.1/v1`，可用环境变量 `DIFY_API_URL` / `DIFY_API_KEY` 覆盖
- 检索词规则以第 2 步为准；结果以 retrieve.py 输出为准
- 不要修改脚本本身
